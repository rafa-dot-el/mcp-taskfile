* Setup

Needs Nix and direnv. =direnv allow= enters a devenv shell with every tool pinned; the shell's Go is the build's Go. Every action is a task, and CI runs the same =task ci= you run locally.

| Task                           | Purpose                                                               |
|--------------------------------+-----------------------------------------------------------------------|
| =task test=, =task test:cover= | unit tests; coverage gate (total and 95% per pure function)           |
| =task lint=                    | golangci-lint (gosec), gofmt, statix, deadnix, actionlint, shellcheck |
| =task sec=                     | govulncheck, gitleaks, osv-scanner                                    |
| =task check=                   | =nix flake check= (pure; builds and tests in the sandbox)             |
| =task check:pins=              | dev shell and package use the same nixpkgs revision                   |
| =task ci=                      | everything above; the same command runs in CI                         |
| =task build=, =task build:nix= | local binary; Nix build (prints the store path)                       |
| =task update=                  | flake and devenv locks (same nixpkgs), Go patch updates               |

Everything is locked: =go.sum= and =vendorHash= (Go), =flake.lock= and =devenv.lock= (Nix). After a Go dependency change set =vendorHash = lib.fakeHash=, run =task check=, and paste the reported hash.

* Releases

Releases are signed tags =vX.Y.Z=; the =VERSION= file is the only place the version is written.

#+begin_src bash :eval never-export
task release:patch    # or release:minor, release:major; release:current tags VERSION as is
#+end_src

The task refuses to run off =main=, with a dirty tree, when =main= differs from a remote, or when the tag exists. It runs =task ci=, bumps =VERSION=, makes a signed =release: vX.Y.Z= commit and signed tag, and pushes both atomically to GitLab and GitHub. The tag push triggers the =release= workflow on GitHub: it checks that the tag equals =v= + =VERSION=, runs the full gate (=ci.yml=), uploads the build to the binary cache, then GoReleaser builds the platform archives from =.goreleaser.yaml= and publishes a GitHub Release with =SHA256SUMS= and build provenance attestations.

=task release:verify= builds the same matrix as a local snapshot and asserts the archive set, checksums, executable formats and version output. Add a platform to =.goreleaser.yaml= only after =CGO_ENABLED=0 GOOS=<os> GOARCH=<arch> go build .= succeeds, and extend =release:verify= with its format.

To publish or republish a release for an existing tag (the first release, v0.1.0, predates the workflow):

#+begin_src bash :eval never-export
gh workflow run release.yml -f tag=v0.1.0
#+end_src

The source is the tag; the release config is the one on the commit that holds the workflow.

* Binary cache

CI pushes every build of =main= and every release tag to the public Cachix cache =rafa-dot-el=. =task cache:push= does the same from a workstation; the token and the signing key come from =CACHIX_AUTH_TOKEN= and =CACHIX_SIGNING_KEY= (or pass) and are never written to disk. The cache serves =nix run= of this repository; a consumer that builds =package.nix= with its own nixpkgs builds the binary itself.
